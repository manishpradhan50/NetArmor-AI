NetArmor AI Privacy Policy

Last updated: October 2, 2026

NetArmor AI is a cybersecurity project that provides automated analysis of URLs, email text, messages and PDF documents. This policy explains what information the application may process and how it is used.

1. Information We Collect

  • Account information: email address, username, authentication identifier and account profile information.
  • Security-analysis input: URLs, email text, message text and PDF files that a user voluntarily submits for analysis.
  • Scan history: scan type, a non-content target label, result, risk score and timestamp may be stored for authenticated users.
  • Technical information: hosting, browser and provider services may generate operational logs according to their own policies.

2. How We Use Information

Submitted information is used to perform the requested security analysis, display results, maintain authenticated scan history and operate the application.

3. AI Assistant

ArmorBot uses the configured Gemini API to answer cybersecurity questions. Do not submit passwords, authentication tokens, payment-card data or other highly sensitive information to the assistant.

4. Google Firebase

Google Firebase is used for authentication and application data (Cloud Firestore). Access to account and scan-history data is controlled through Firebase Authentication and Cloud Firestore security rules in the supplied project schema.

5. PDF Processing

Uploaded PDFs are processed by the NetArmor backend to extract text, hyperlinks and selected PDF indicators. The application is intended to analyze the document; it does not guarantee that a document is safe or malicious-free.

6. Scan History

For privacy, the frontend records a short target label rather than storing the submitted email or message body in scan history. Users can view their own history. Authorized associate accounts can view platform scan records as required for the security dashboard.

7. Data Retention

Scan-history records remain in the configured Cloud Firestore database until they are deleted by an authorized administrator or through a future data-retention process. Hosting and third-party providers may retain operational logs according to their own policies.

8. Security

Production deployments should use HTTPS, Firebase Authentication, Cloud Firestore Security Rules and server-side storage for private API credentials. Secret service keys and Gemini API keys must never be included in browser or extension code.

9. Browser Extension

The Chrome extension can send the active page URL or user-entered content to the NetArmor backend when the user requests a scan. The extension should not be used to submit confidential information.

10. Cookies and Local Storage

Firebase authentication may use browser storage (IndexedDB / LocalStorage) to maintain a signed-in session. The application may also use session storage for temporary profile information and local storage for interface preferences.

11. Third-Party Services

NetArmor AI may rely on Google Firebase, Google Gemini and its hosting provider. Their own terms and privacy policies may apply to data processed by those services.

12. Children's Privacy

The project is not intentionally designed to collect personal information from children. Users should avoid submitting another person's personal or confidential information without appropriate authorization.

13. User Choices

Users can stop using the service, sign out, and contact the project administrators regarding account or stored scan-history questions. Account deletion procedures depend on the configured Firebase deployment.

14. Changes

This policy may be updated when the application's data practices change. The date at the top will be updated when a new version is published.

15. Contact

For privacy questions, contact the NetArmor AI project team through the contact information published with the project.
